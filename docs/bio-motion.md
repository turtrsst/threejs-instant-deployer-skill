# Auto-Procedural Bio-Motion

## Selection contract

1. Actual GLTF animation clips with tracks → `AnimationMixer`, `animationMode:'native-animation'`.
2. No native animation + recognized/explicit biological preset → GPU vertex deformation, `animationMode:'procedural-vertex-shader'`.
3. No suitable preset or explicit opt-out → `animationMode:'static'`.

`manifest.bioMotion` is only a name-heuristic recommendation. It does not change the binary or `xray.hasAnimations` and never satisfies scout `--animated`. Procedural movement has no animation clip names or skeletal joints to invent. Asset names override less-specific search-query words when choosing a recommendation. Review every recommendation, especially ambiguous words such as plant/coral/animal sculptures.

## Files and entry points

- Source factory: `mcp-server/codeDeployer/bioMotion.ts`, compiled into `dist/codeDeployer/bioMotion.js`; exported via package `./bio-motion` and `./browser`.
- Standalone template: `templates/bio-motion-injector.js`, generated by `scripts/build-templates.mjs` during `npm run build`. Commit the template when source changes. It imports only `three`, not dist or the skill package.
- Standalone bridge: `templates/smart-deploy.js`, imports only Three.js, its addons, and the adjacent injector template. Copy both templates together into a project.
- AST injector embeds the same factory source into output JS/TS/HTML, so the target project needs no skill package. This necessarily increases output source size.

Three.js r180 WebGLRenderer is the tested shader-chunk contract. `three` is an optional peer for template users; server-only scouting does not need a browser renderer. Keep core and addons versions identical. WebGPURenderer/TSL is not supported. Build tests inspect patched r180 shader sources and uniform/material state; no GPU/browser compilation is performed by default tests.

## Direct injection

```js
import { injectBioMotion } from './templates/bio-motion-injector.js';

const motion = injectBioMotion(gltf.scene, {
  preset: 'fish_swim',
  spineAxis: 2,        // Optional: 0 = X, 2 = Z; omitted = automatic
  spineDirection: 1,  // +1: head at minimum axis; -1: head at maximum
  phaseOffset: 0.7    // Optional: default random per instance
});
// Every frame (elapsed is seconds): motion.update(elapsed);
// motion.setSpeed(3); // Can be called before shader compile; 0 pauses phase advance.
// Teardown, before disposing geometry/materials: motion.dispose();
```

`setSpeed` sets the phase multiplier at the current elapsed timestamp; changing speed may create a phase jump. For a continuous interactive pause freeze elapsed time instead (as in the lab demo). Preset controls accept finite, nonnegative speed/frequency/amplitude/roll/bob; stiffness must be >1 for stable endpoint derivatives. Unknown presets, invalid directions/axes, duplicate injection, and missing eligible geometry fail explicitly. No default-to-plant behavior is used for unknown names.

Three presets retain the requested parameters: fish speed 6.5/frequency 4.2/amplitude .14/roll .12/bob .025/stiffness 1.85; plant 1.8/2.5/.18/flutter .035/stiffness 1.6; coral 2.2/3/.10/flutter .05/stiffness 1.3. The current coral model uses radial pulse + vertical drift; flutter is reserved and not used by that mode. These are stylistic presets, not measured biological simulation parameters.

## Existing primitive deployment

`createAssetDeployer` retains bottom-pivot replacement, uniform measured scale, parent transform, fallback mesh, Meshopt decoding, PBR setup and lifecycle cleanup. Its sixth argument can override preset/settings:

```js
const handle = assets.deploy(placeholder, manifest, url, renderer, scene, {
  bioPreset: 'fish_swim',
  bioOptions: { spineAxis: 2, spineDirection: -1, phaseOffset: 0 }
});
await handle.ready;
console.log(handle.animationMode, handle.warnings);
assets.update(delta, elapsed); // Or assets.update() using internal performance time.
// Teardown: handle.dispose() or assets.dispose().
```

`bioPreset:null` / `'none'` disables fallback, `'auto'` uses name inference. Native clips always take priority even if a bioPreset was explicitly provided. The AST injector supports `--bio-preset auto|none|fish_swim|aquatic_plant|soft_coral`; MCP `inject_three_code` exposes the corresponding `bioPreset` field. Static fallback shaders do not turn model animation metadata true. Runtime uses actual loaded clips, not blindly trusting a stale manifest.

## New-object smart template

```js
import * as THREE from 'three';
import {
  deploySmart3DModel,
  updateAllDeployedModels,
  disposeAllDeployedModels
} from './templates/smart-deploy.js';

const handles = [];
for (let i = 0; i < 5; i++) {
  handles.push(deploySmart3DModel('/models/BarramundiFish.glb', {
    scene,
    position: new THREE.Vector3(i - 2, 1, 0),
    rotationY: 0,
    manifest, // Measured recommendedScale required, no guessed default.
    bioPreset: 'fish_swim'
  }));
}
await Promise.all(handles.map(handle => handle.ready));
let elapsed = 0;
const clock = new THREE.Clock();
renderer.setAnimationLoop(() => {
  const delta = clock.getDelta(); // Read once, don't call getElapsedTime again.
  elapsed += delta;
  updateAllDeployedModels(delta, elapsed);
  renderer.render(scene, camera);
});
// Teardown: disposeAllDeployedModels();
```

Each handle has `ready`, `model`, `mixer`, `bioController`, `animationMode`, `warnings`, and idempotent `dispose()`. `onLoaded(handle)` and `onError(error)` are optional. Handle the ready promise rejection yourself; callbacks do not consume errors. Disposing during an in-flight load releases the eventual asset without adding it to scene. Updaters are removed on disposal.

Positions for **new objects** are bottom-center positions already; no primitive-half-height correction occurs in this API. The bridge configures shadows/material intensity and Meshopt decoder, but the application must provide adequate lighting/environment, enable renderer/light shadows, and configure any additional texture loaders (e.g. KTX2) required by the asset. Native animations receive a random start offset; procedural instances receive independent random phase uniforms. Each call loads a separate model; this bridge is not an asset cache/instancing system.

## Coordinate and shader design

All eligible mesh bounds are transformed to a single **model-root space** via `inverse(root.matrixWorld) * mesh.matrixWorld`. Global placement/rotation/scale is excluded. Every mesh shares the same root bounds, axis and phase, preventing per-mesh tail/fin discontinuities caused by separately normalizing each local geometry. Mesh→root and inverse matrices map positions and normals consistently. Child transforms must remain static while injected; reinject after editing them.

Auto-spine chooses only the longest **horizontal X/Z axis**. It cannot infer anatomical head direction, diagonal skeletons or Y-oriented bodies. Default +1 means minimum coordinate = head, maximum = tail. Review direction visually or override; reorient vertical fish first. Vertices with insufficient subdivisions cannot form smooth waves.

`bioDeform(p, out J)` returns both displaced root-space position and an analytical Jacobian. Fish derivatives include sinusoidal phase, envelope stiffness and roll; plant derivatives include primary sway, flutter noise and root mask; coral derivatives include radial pulse and height mask. Surface normals use `J^-T * n` via cofactors, then return to local coordinates before `defaultnormal_vertex` applies Three.js normal transforms. Tangents use the forward Jacobian for tangent-space normal mapping. A near-singular Jacobian falls back to the input normal. High amplitudes/frequencies can still fold geometry; presets are not collision/volume constraints.

Position deformation runs before `project_vertex`, after the ordinary position pipeline; surface normal deformation runs before `defaultnormal_vertex` rather than after `begin_vertex` (which is too late for already-transformed normals). MeshDepthMaterial and MeshDistanceMaterial use identical position code/time so directional/spot and point-light shadows follow. Three.js WebGLShadowMap copies alpha/cutout maps and side state from source groups each draw; enabling shadows remains the application's responsibility.

Materials are cloned to avoid cross-instance mutation; prior compile hooks and cache keys are composed, not silently discarded. Original material arrays, custom shadow materials, culling and userData are restored on disposal. Cloned materials/shadow materials are disposed, but shared source textures/geometry are not disposed by the injector alone. Deployer handles own loaded GLTF resources and dispose those separately, after removing the shader controller.

## Limits and verification

- Static Mesh only. SkinnedMesh, InstancedMesh, BatchedMesh, morph geometry and ShaderMaterial/RawShaderMaterial are skipped with warnings; no eligible mesh is an explicit error. A compatible native animation path is preferred for those assets.
- Existing custom shaders, displacement maps, clipping tricks and callbacks that alter position/normal may require custom integration. Preserving hooks cannot make arbitrary shader modifications compatible.
- GPU deformation does not update CPU raycasting, collision, bounding boxes or rest-pose X-Ray. Frustum culling is temporarily disabled for patched meshes to avoid disappearing fish/foliage; this has a performance cost.
- Root pinning is at the combined minimum local Y, not an inferred stem anchor per separate plant. Split unrelated plants into separate roots/controllers.
- Specular response also depends on PBR textures, tangent validity and environment. The shader cannot guarantee physical realism or repair incorrect anatomy/orientation.
- Shader phase does not implement swimming paths, steering, boids or buoyancy physics. Bobbing fish may intersect the floor if placed at floor height; place them in water clearance above the substrate.
- `/bio.html` provides a browser review surface with synthetic multi-mesh fish/plant/coral, spine/direction controls, speed, pause and directional/point lights. Run on the target GPU and inspect shader errors/shadows before declaring visual verification complete.


## Interactive uniform setters

Controllers expose `setAmplitude(value)` and `setFrequency(value)` in addition to `setSpeed(value)`. Values must be finite/nonnegative; updates reach shared `uBioAmp`/`uBioFreq` objects before shader compile and all patched surface/depth/distance materials afterward. No material traversal or `userData.bioShader` lookup is needed. `maxAmplitude` injection option can cap amplitude (must cover the initial amplitude); `amplitudeLimit` reports the cap and `disposed` reports lifecycle state. Ordinary injection defaults to no explicit cap; increasing amplitude does not automatically expand external CPU collision proxies. Instanced schools impose their construction-time conservative reserve. See [Director Studio](aquarium-director.md).
