# Interactive Aquarium Director Studio (lil-gui)

`templates/aquarium-director-gui.js` exports `createAquariumDirectorGUI(options)` and three immutable `ATMOSPHERE_PRESETS`: Zen Crystal Daylight, Deep Bioluminescence Night and Golden Hour Amazonas. It binds the repository's existing controllers; it does not create a second simulation/render loop or replace PBR shaders.

The panel is opt-in. It starts at **Custom** and reads current live settings without applying arbitrary defaults, reducing population to 350 or installing a mood preset on mount. The GUI owns only its DOM/controllers, not the scene, renderer, fish, materials or effects. Dispose it before replacing its bindings.

## Setup: allocate capacity once

```js
import {InstancedBoidsAquariumManager} from './templates/instanced-boids-manager.js';
import {createAquariumDirectorGUI} from './templates/aquarium-director-gui.js';

// gltf = static GLB loaded with required decoders; manifest = measured scout output.
const fishAquarium = InstancedBoidsAquariumManager.fromGLTF(scene, gltf, 1000, {
  recommendedScale: manifest.recommendedScale,
  bounds: aquariumWorldBounds,
  activeCount: 350,
  maxAmplitude: 0.45,
  obstacles: [rock],
  castShadow: false
});
const director = createAquariumDirectorGUI({
  renderer, scene,
  sunLight,
  postFX,
  fishAquarium,
  causticControllers: caustics, // Actual injectWaterCaustics controllers.
  bubbles,                    // Actual InteractiveBubbleSystem.
  plantControllers            // Actual aquatic_plant Bio-Motion controllers.
});
// In the existing single render loop, AFTER postFX.render(delta,elapsed):
// director.syncFocusDisplay();
// On unmount: director.dispose() BEFORE postFX/FX/manager/source asset disposal.
```

Use the same Three.js/addons version as the other modules: **r180 WebGLRenderer**. The browser template imports the bundled `three/addons/libs/lil-gui.module.min.js`; no separate GUI npm dependency/CDN is required. Typed/server-safe package entry `threejs-instant-deployer-skill/aquarium-director` exports `createAquariumDirectorFactory(THREE,GUI)`; it does not instantiate lil-gui or access DOM/clipboard during import.

Source is `mcp-server/codeDeployer/aquariumDirectorGui.ts`; template is generated by `npm run build`. Copy all needed sibling templates/helpers when using the complete scene. [cinematic-main.js](../examples/cinematic-main.js) now allocates capacity 1,000 with 500 visible, reserves amplitude .45, and creates/disposes this panel around the existing cinematic helper.

## What zero-reallocation population scaling means

`fishAquarium.count` remains the **allocated capacity**. `setActiveCount(n)` (or assigning `activeCount`) sets `.count=n` on **every** InstancedMesh part, not just the first body geometry. Bounds: integer **0..capacity**. It updates `stats.activeCount`; `stats.capacity` and the original capacity stay fixed.

The count setter does not recreate/dispose geometry, material, texture, instance attribute or instanceMatrix buffers; it does not fill matrices, mark their buffers dirty, regenerate random offsets or rebuild the shader. The next render uses a different instance draw count. This is the precise **zero GPU-buffer reallocation** claim—not a promise of microsecond latency, zero JS/DOM allocations, no shader compilation elsewhere or no frame stutters on every device.

CPU simulation remains **one Boid per preallocated cluster**. With capacity 1,000 / clusterSize 64, 16 centers continue simulating whether 1,000, 150, one or zero fish are drawn. This preserves trajectories for reappearance. Hidden centers still participate in the cluster flocking field; this is not an active-only physics solver. Rendering fewer fish can reduce GPU vertex/fragment work, but does not proportionally reduce CPU cluster work or other post-processing/shadow costs. There is no new per-fish CPU loop.

Instance-to-cluster mapping remains `instanceIndex % clusterCount`. `getInteractionSources()` returns a borrowed cached list of only centers used by the visible prefix, so no visible fish means no fish bubble-influence sources; it remains coarse cluster interaction, not exact individual positions. Do not mutate that returned list.

Changes to **capacity, clusterSize, geometry, layout, world bounds or deformation reserve** require reconstruction, not a population slider. The `/instanced.html` demo preallocates 2,000 fish; its population sliders only change counts. Cluster/shadow/FX reset controls still rebuild the school and recreate the GUI bindings, clearly separate from population scaling.

## Live controls and actual runtime APIs

| Panel field | Runtime action |
|---|---|
| activeFishCount | `manager.setActiveCount(n)` for all parts |
| swimSpeed | `setMaxSpeed`, updates underlying cluster solver and clamps velocities |
| tailBeatSpeed | `setTailSpeed` → shared `uBioSpeed` |
| tailWaveAmplitude | `setAmplitude` → shared `uBioAmp`, within reserved max |
| tailWaveFrequency | `setFrequency` → shared `uBioFreq` |
| currentSpeed | Broadcast plant `setSpeed`; **flora motion rate**, not a physical current velocity field |
| plantSwayAmplitude | Broadcast plant `setAmplitude`; unitless displacement factor, **not a calibrated sway angle** |
| causticsSpeed / causticColor | Actual caustic controller `uniforms.uCausticSpeed/uCausticColor`, available before compile |
| bubbleRiseSpeed | `bubbles.setRiseSpeed`, a multiplier on existing sampled CPU rise speeds |
| bubbleOpacity | `bubbles.setOpacity` → shader `uBubbleOpacity`, not unused material.opacity |
| focusDistance | `postFX.setFocusDistance(value,true)`; manual immediate snap releases tracking |
| aperture / maxBlur | `postFX.setConfig` |
| bloomStrength / bloomRadius / bloomThreshold | `postFX.setConfig`; radius restricted to 0..1 |
| godRayIntensity / chromaticAberration / waterTint | `postFX.setConfig`, keeping internal config consistent |
| exposure | `postFX.setConfig({exposure})`; renderer field only when no post controller is bound |
| waterFogColor | Existing fog color and Color background only; texture/cubemap backgrounds are not replaced |
| fogDensity | Only offered for FogExp2; linear Fog is not given a fake density control |
| sunIntensity | Supplied Three.js Light intensity |

Optional controllers are actually optional: folders/fields are omitted if unavailable, not fake working sliders. Supply all references before creating the GUI; plant/caustic bindings are snapshotted. Recreate after adding/removing controllers. No automatic GLB loading or inferred asset scale is performed by the panel.

`causticControllers` accepts controllers from `injectWaterCaustics` or patched material references. Legacy argument `causticsFloor` is supported by inspecting its material's **`userData.causticUniforms`**, not looking for nonexistent PBR `material.uniforms`. Pass all controllers when adjusting the whole school/floor, not just one surface.

Three presets are creative settings, not physically calibrated environments. Selecting one applies every supported field consistently, including exposure through the post API, lens tint, caustic color, fog and sun. Unsupported optional fields are skipped; fish count, focus tracking and plant settings are not implicitly reset. Editing a parameter afterward marks the mood Custom.

### Deformation safety

Bio-Motion controllers now expose `setAmplitude(value)` and `setFrequency(value)` alongside `setSpeed(value)`. They mutate **shared uniform objects**, so calls work before compilation and affect every surface/depth/distance material using that controller. They do not traverse materials looking for a nonexistent `userData.bioShader`. Uniforms are named `uBioAmp`, `uBioSpeed`, `uBioFreq`, not `uAmplitude`/`uSpeed`.

For an instanced school, constructor `maxAmplitude` defaults to its initial fish amplitude. The initial proxy includes the reserved maximum's deformation bound, and the underlying Bio controller also enforces it. Raise `maxAmplitude` **at construction** to expose a wider safe GUI range; attempting to exceed it later throws. Reserving more can make a narrow tank/obstacle layout infeasible. If also overriding `deformationMargin` while opting into higher amplitude, that margin must cover the conservative reserve.

Ordinary plant/coral Bio controllers can use `bioOptions.maxAmplitude` to cap their GUI range. Without a cap the uniform setter permits finite nonnegative values; frustum culling is already disabled for GPU displacement, but external obstacle/picking systems are not automatically expanded. If used with individual Boids or custom CPU proxies, reserve adequate margins there too. All plant controllers in a broadcast group must have a compatible shared amplitude range; use separate panels/groups for incompatible limits. Group controls initially show a representative first value, not a complete per-plant state checkpoint.

Cruise speed must be positive and cover every cluster's `minSpeed / speedMultiplier`. `minimumCruiseSpeed` reports the allowed lower bound. The setter clamps current velocities to each valid range; assigning a random new property does not affect the solver. Frequency/speed tuning can change wave phase abruptly; no hidden geometry rebuild or automatic phase-continuity solver is claimed.

`scatterFish()` is **seeded cluster startle**: bounded new headings/velocities at each cluster's configured speed, acceleration reset, no teleporting of centers and no per-fish CPU data loop. The next normal solver steps apply constraints and heading interpolation. Local GPU offsets are unchanged; this is not independent fish explosion physics or a temporary 2.8× speed bypass of obstacle constraints.

## API / ownership

- `gui`: lil-gui instance, for supported presentation customization.
- `state`: GUI binding object. Change runtime through the API, not by mutating this object directly.
- `applyConfig(parameterPatch)`: validates supported numeric/color ranges before applying. Unknown/unavailable keys are rejected. It marks mood Custom. The validation prevents partially applying an invalid patch; arbitrary external controller exceptions are not a general cross-system transaction/rollback mechanism.
- `applyPreset(name)`: apply one named atmosphere preset, preserving unrelated controls/tracking.
- `syncFocusDisplay()`: read current focus after render, update only the displayed value; never call a setter or detach tracking. No GUI `.listen()`/extra animation loop is installed.
- `syncDisplay()`: additionally synchronize population changed by another host control.
- `getConfig()`: shallow parameter snapshot including mood label, with current focus/population synchronized.
- `exportConfigJSON()`: pure string result `{version:1,preset,parameters}`; no methods, Three.js objects, DOM references or hidden simulation state.
- `importConfigJSON(text)`: validate version and apply supported parameters; mood becomes Custom. This is parameter restoration, not asset loading or restoration of tracked Object3D references, phases/velocities/camera pose/native animation time. Focus snapshot imports as manual distance.
- `copyConfigToClipboard()`: async `{copied,json,error?}`. Clipboard denied/unavailable resolves with `copied:false` and still returns JSON. No automatic console dump or silent unhandled rejection.
- `scatterFish()`: cluster startle, requires a bound fish manager.
- `dispose()`: idempotent `gui.destroy()` and internal reference cleanup. Tuning persists, borrowed resources remain alive. Other methods reject after panel disposal or when a bound runtime controller has been disposed.

Optional GUI construction arguments: `container`, positive `width` (default 310), `title`, `clipboard` adapter, `onExport(result)`, `onError(error)`. The copy button reports success/failure in its status field. Without clipboard support, use the returned JSON API or `onExport` to implement your application's download dialog. Clipboard is only accessed on explicit export/copy actions, not import or module startup.

```js
const json = director.exportConfigJSON();
director.applyConfig({activeFishCount:800, tailWaveFrequency:4.8, bubbleRiseSpeed:1.2});
director.applyPreset('Deep Bioluminescence Night');
director.importConfigJSON(json);
const result = await director.copyConfigToClipboard();
if (!result.copied) showExportText(result.json); // Application-owned UI.
```

Destroy GUI **before** replacing school/post/FX bindings. The panel does not undo a chosen preset or dispose the renderer/scene/controls/shader materials/loaded textures. It does not call `updateAllDeployedModels`, requestAnimationFrame or renderer/composer rendering itself.

## Plants with measured assets / one updater

```js
const plant = deploySmart3DModel('/models/anubias_plant.glb', {
  scene,
  manifest: plantManifest, // Measured recommendedScale, not a guessed literal.
  position: new THREE.Vector3(-1.5, 0, 0.4),
  bioPreset: 'aquatic_plant',
  bioOptions: {maxAmplitude:0.5}
});
await plant.ready;
const plantControllers = plant.bioController ? [plant.bioController] : [];
// Create the panel with this array after the load, or recreate when bindings change.
```

Native animation clips still take precedence; `bioController` can be null and should not be fabricated for an animated plant. The cinematic helper already calls the **one global updater** for deployed assets, so do not call `plant.bioController.update` or the global updater a second time. Direct standalone synthetic Bio controllers, which are not registered with the deployer, do need their own one `update(elapsed)` call; the demo makes that distinction.

In the application loop, read `clock.getDelta()` once and accumulate elapsed. Call the existing cinematic helper's `render(delta,elapsed)` once, then `director.syncFocusDisplay()`. Do not add `clock.getElapsedTime()` after getDelta, a second fish update, another global updater or another scene render just to support the GUI.

## Demo and validation limits

Run `npm run demo`, open `/instanced.html`, and enable **DIRECTOR STUDIO (PANEL BELOW)**. Enable cinematic post FX for lens/Bokeh controls, and caustics/bubbles to see their controls; the panel recreates bindings when these optional systems reset. Two explicitly synthetic leaf planes demonstrate flora amplitude/rate. Population changes do not invoke the reset path. All-pass counters and visible/capacity counts distinguish rendering cost from the fixed preallocated CPU cluster budget.

Automated tests use real Three.js geometry/materials/managers with an injected GUI stub for DOM-independent checks. They verify immutable buffer identities/versions across population changes, multi-part counts, precompile uniform sharing, amplitude reserves, bounded seeded scatter, actual runtime setters, presets, focus synchronization, export/clipboard failure, and borrowed-resource disposal. Generated modules import under Node and Vite bundles the actual lil-gui addon. Those checks are **not live browser GUI interaction, GPU shader appearance or measured microsecond/FPS verification**.

Bloom remains luminance-based, ray/snow effects remain stylized screen-space, cluster interactions remain approximate and instanced fish do not support exact GPU raycast picking. These limitations are unchanged by adding sliders. Profile full-frame GPU/memory/input responsiveness on the target device; no universal smoothness/60 FPS guarantee is made.

## Ringkasan Indonesia

Panel menggunakan API yang benar dan uniform bersama sebelum kompilasi. Populasi mengubah draw count semua mesh part dalam kapasitas tetap, tanpa membuat ulang buffer GPU; CPU tetap menjalankan cluster yang dialokasikan. Amplitudo ikan dibatasi cadangan deformasi yang dihitung sejak awal. Scatter bekerja pada cluster, bukan fishData per ikan.

Fokus manual memakai API post FX, sedangkan sinkronisasi angka tidak melepas tracking. Bubble opacity memakai uniform shader, tint/exposure memakai konfigurasi post yang konsisten, dan fogDensity hanya tersedia untuk FogExp2. Preset tidak diterapkan diam-diam saat panel dibuat. Ekspor JSON memiliki versi dan menangani clipboard yang ditolak. Dispose panel lebih dulu saat mengganti binding; aset scene bukan milik GUI.


## Optional procedural audio binding

Supply `audioSynth` from [underwater-audio-synth.js](underwater-audio.md) for an opt-in Enable/Resume button, `audioMasterVolume`, `audioDroneIntensity`, `audioBubbleRate` (0..8 clusters/sec), `audioZenChimesEnabled` and `audioMuted`. Current-motion edits route to both flora and synth; without flora an ambient-motion control is offered. GUI scatter triggers the synth accent only when it can play. Mount/preset/JSON import never initializes audio; parameter JSON contains scalars/booleans only, not consent/AudioContext state. `syncDisplay` also reads external audio mute/volume. The GUI borrows the synth; dispose GUI before audio, keep one synth through school/post resets. Enable/Resume explicitly unmutes after successful activation.

## Optional interactive feeding binding

Pass `fishFeeder` for an Interactive Feeding folder: canvas-input `feedingEnabled`, Drop Food at Tank Center and Clear Food / Ripples. `syncDisplay()` reads the external enabled flag. Only the boolean is serialized; mount/import/presets never spawn food or activate audio. GUI borrows feeder, and CPU cluster-center interactions are approximate, not per-GPU-fish consumption. Dispose GUI before feeder. [Feeding API and single-loop ownership](interactive-feeder.md).

## Optional dynamic day–night cycle

[Day–Night Cycle](day-night-cycle.md) interpolates optical keyframes and normalized HDR PBR emission in the existing frame owner. Register actual mesh/material parts after earlier shader injection; restore in reverse disposal order. No per-fish matrix writes, native animation replacement or emission in depth/normal/shadow shaders. `dayNightOptions` opts the cinematic helper into ownership; Director `dayNightCycle` exposes time/auto/duration/color and mirrors current optical values for JSON. The updating cycle takes precedence over independent optical presets, including when its hour is paused. It borrows lighting/post/caustic resources and leaves the last optical values on disposal. Screen rays and biological masks are stylized, bloom is not selective and PMREM is not regenerated. See the contract for bounds/axis validation and browser GPU verification limits.

## Optional cinematic camera ownership

[Camera Director](cinematic-camera-director.md) owns OrbitControls updates or automatic macro/CPU-cluster shots and synchronizes lens/focus through the real post API. `cameraOptions` opts the cinematic helper into construction, one update before day-night projection/render and reverse disposal; `cameraDirector` opts the GUI into mode/stand-off/auto/rotation controls and current aperture/JSON synchronization. C/N key bindings are explicit and ignore GUI typing. Zero visible clusters fall back safely. No per-individual GPU fish tracking, matrix readback/upload, true fisheye distortion or collision-safe rock/frustum navigation is claimed. Do not independently call controls.update or add another clock/render loop while bound.

## Optional water surface / impact binding

[Underwater Surface](underwater-surface.md) combines dielectric Fresnel/TIR with procedural sky/mirror colors, analytic height-field normals and eight bounded ripple slots. Helper `surfaceOptions` derives the audited tank plane and runs after day-night/before the existing post render; GUI `waterSurface` binds validated scalar setters. `surface.bindFeeder(feeder)` uses the new bounded `onFoodSpawn` subscription after successful nonzero drops, not a method monkey-patch. Mean-plane contact and camera medium classification are approximate; no actual reflected aquarium image, full Gerstner/CFD, dynamic Boids water-boundary collision or extra render/capture loop is claimed. Dispose subscriptions/owned mesh/material/geometry; borrow lights/scene/feeder and retain post depthWrite:false/focus exclusion.

## Local preset file management

[Preset Management](preset-management.md) adds Export Preset (JSON) and Import Preset (JSON) to the existing panel, retaining string/clipboard APIs. Version-1 parameters are snapshotted from live bound controllers and fully prevalidated (256 KiB UTF-8 limit, supported schema/keys/types/ranges/capacity) before setters apply them. Files do not serialize functions, geometry, full simulation state or audio consent. Temporary anchors/object URLs and picker/read callbacks/timers are owned/cancelled by GUI disposal; late reads never apply after replacement/disposal. Browser file APIs remain lazy; actual OS picker/download behavior needs target-browser testing.
