# Underwater Post-Processing Stack

`templates/underwater-postprocessing.js` exports `createAquariumPostProcessing(renderer,scene,camera,options)` and `UnderwaterLensShader`. It is optional: keep the direct renderer path when post-processing is too expensive or incompatible.

## Pipeline and honest scope

Five EffectComposer passes run in order:

1. **RenderPass:** scene color in linear HDR, into a HalfFloat WebGLRenderTarget.
2. **Deformation-aware BokehPass:** per-mesh/per-material-group packed depth, then screen-space depth-of-field.
3. **UnrealBloomPass:** luminance-threshold glow.
4. **ShaderPass:** chromatic edge separation, micro-ripple, stylized rays, luminance-based water tint, procedural screen-space marine snow, vignette.
5. **OutputPass:** final ACES exposure/tone mapping and sRGB output conversion once.

MSAA is a **render-target option**, not another image pass. The stack requests 4 samples by default and queries RGBA16F-supported sample counts on the current WebGL2 context, also capped by `maxSamples`. `state.samples` reports the selected count, which can be 2 or 0. Multisampling does not guarantee that all post-processed/DoF/depth edges are alias-free.

**Bloom is not selective bloom.** Any pixel above the threshold can glow—rocks, background, lights and fish alike. Thresholds cannot identify “only caustics/bubbles/scales.” Keep highlights under control using actual lighting/exposure/materials, and inspect real assets. This module does not implement layer masks or a second selective-emission composer.

**Rays/snow/tint are stylized screen-space effects.** Rays do not sample light occlusion, shadows or participating media. Marine snow is a moving procedural overlay, not world-space particles, depth-tested dust or fluid simulation. Water tint follows luminance, not reconstructed water depth. Use scene fog for distance cues; none of these constitute physical volumetric scattering/refraction. The existing interactive bubbles remain actual world-space Points sprites.

Bokeh is screen-space approximate DoF, not a physically calibrated camera. Foreground silhouettes, transparent glass, thin geometry and disocclusion can exhibit halos. Tuning aperture/maxBlur reduces some artifacts, not all of them.

## Prerequisites / imports

- Matching **Three.js r180 WebGLRenderer + addons** (`three@0.180.0`). No WebGPU/TSL.
- WebGL2 with **EXT_color_buffer_float** for renderable HDR half-float targets. Unsupported contexts fail explicitly; there is no implicit low-quality fallback.
- Standard perspective or orthographic camera depth. **Logarithmic/reversed depth buffers are rejected** because stock Bokeh depth reconstruction does not match them.
- Serve through a bundler/dev server, not `file://`. Browser template imports the six corresponding `three/addons/postprocessing/*.js` modules.
- Node/server package export `threejs-instant-deployer-skill/underwater-postprocessing` exposes `createAquariumPostProcessingFactory(THREE,addons)`. It does not instantiate a renderer or read window at import time. Browser template supplies those dependencies for you.

Source: `mcp-server/codeDeployer/underwaterPostprocessing.ts`. Template is regenerated by `npm run build`; edit the source, not the generated file. Only one live stack may own a renderer at once; dispose before recreating.

## Existing scene integration

```js
import {createAquariumPostProcessing} from './templates/underwater-postprocessing.js';

const post = createAquariumPostProcessing(renderer, scene, camera, {
  container: stageElement, // Stable-size container, not necessarily the browser window.
  focusDistance: 5.5,
  aperture: 0.0014,
  maxBlur: 0.006,
  bloomStrength: 0.42,
  bloomThreshold: 0.72,
  godRayIntensity: 0.18,
  maxPixelRatio: 1.5,
  enableClickToFocus: true,
  focusObjects: [floor, rock]
});
const clock = new THREE.Clock();
let elapsed = 0;
renderer.setAnimationLoop(() => {
  const delta = clock.getDelta(); // Read the clock ONCE.
  elapsed += delta;
  // Update school, mixers/Bio-Motion, caustics, bubbles exactly once here.
  controls.update();
  post.render(delta, elapsed); // Replaces renderer.render(scene,camera).
});
// Teardown: stop loop, post.dispose(), then scene-owned FX/manager/assets.
```

Do not call `clock.getElapsedTime()` after `getDelta()`—it advances the same clock again. Do not additionally call `composer.render` or `renderer.render` for the scene in this loop. OutputPass must remain last; do not add a second gamma/tone-map pass.

The stack configures ACESFilm, exposure and sRGB while active. `dispose()` conditionally restores the previous values if they still match values owned by the stack. Renderer/camera/scene/controls are borrowed, never disposed. If another system needs to own output/tone mapping simultaneously, do not stack two conflicting controllers.

## Complete instanced + atmosphere example

[examples/cinematic-main.js](../examples/cinematic-main.js) is a complete bundler entry with renderer, camera, OrbitControls, hemisphere/directional lights, a PMREM RoomEnvironment, PBR floor, explicitly synthetic rock, measured static GLB loading and one clock/render loop. It expects processed `/models/BarramundiFish.glb` plus `/models/BarramundiFish.manifest.json`, not downloaded binaries embedded in this repository.

It uses [createCinematicAquarium](../examples/cinematic-aquarium.js):

```js
import {createCinematicAquarium} from './examples/cinematic-aquarium.js';

const aquarium = await createCinematicAquarium({
  renderer, scene, camera, controls,
  url: '/models/BarramundiFish.glb',
  manifest: fishManifest,
  bounds: auditedWorldBounds,
  obstacles: [rock],
  floorMaterial: floor.material,
  count: 500,
  bubbleCount: 350,
  schoolOptions: {castShadow: false},
  postOptions: {container: stageElement, maxPixelRatio: 1.5}
});
const clock = new THREE.Clock();
let elapsed = 0;
renderer.setAnimationLoop(() => {
  const delta = clock.getDelta();
  elapsed += delta;
  aquarium.render(delta, elapsed);
});
// On unmount: stop loop, aquarium.dispose(), then dispose caller-owned scene resources.
```

This helper owns the instanced loaded source, material caustics, bubbles and post stack. Its `render()` advances the clustered manager, caustics, bubbles, the **one global deployed-model updater**, controls and post output. Do **not** also call `updateAllDeployedModels`, the underwater wrapper's update, or a second scene renderer outside it. It restores borrowed floor hooks during reverse-order cleanup; it does not dispose the caller's floor/obstacles/renderer/controls. Loader/constructor failures release the resources already created.

It defaults focus to the first **CPU cluster center**, not a particular GPU fish. Bubble influence also uses cluster centers and is coarse approximation. Use a world Vector3 representing the school center or another stable Object3D for a different focal subject. Exact per-fish instanced raycasting/pose readback is not provided by the clustered manager.

For async mounting/unmounting, use the guard in `cinematic-main.js`: if an awaited helper finishes after disposal, immediately dispose its result and do not start a loop. Keep source textures alive until manager disposal. Native skeletal/morph assets must use the existing native-animation path; the instanced loader rejects them rather than silently discarding clips.

The imports intentionally use existing **`underwater-fx.js`**, `injectWaterCaustics` and `InteractiveBubbleSystem`; there is no `underwater-atmosphere.js` / `createCausticsFloor` API. A floor is a normal PBR Mesh with caustics attached. Downloaded rock scale must likewise come from its own measured manifest, not a literal guessed `recommendedScale`.

## API

| Method / field | Behavior |
|---|---|
| `composer` | Owned EffectComposer; exposed for inspection, not separate render/dispose calls |
| `passes` | `renderPass`, `bokehPass`, `bloomPass`, `underwaterPass`, `outputPass` |
| `state` | Snapshot of CSS width/height, pixelRatio, actual samples, current/target focus distance, target-in-front status |
| `render(delta,elapsed?)` | Finite nonnegative delta, monotonic elapsed seconds; omitted elapsed is accumulated. Updates focus/lens then renders once |
| `resize(width?,height?,pixelRatio?)` | Positive CSS dimensions and ratio; defaults to container dimensions or renderer logical size; DPR capped by maxPixelRatio |
| `setFocusTarget(Object3D\|Vector3\|null)` | Track world target, or detach without snapping current focus |
| `setFocusDistance(distance,immediate=false)` | Positive camera-axis distance; releases tracking and clamps to camera clip range; optional immediate snap |
| `focusTarget` | Current tracking reference, or null |
| `setConfig(patch)` | Validated atomic update; unknown keys rejected |
| `dispose()` | Idempotent; removes listeners/observer, pass resources/depth clones, both composer targets/copy pass; no double-dispose of the input target |

All methods except dispose reject use after disposal. `state` is a snapshot, not a mutable tuning interface; use `setConfig`/focus methods.

### Focus correctness

Bokeh needs the **camera-space negative Z depth**, not `camera.position.distanceTo(target)` or `Raycaster.hit.distance`. The camera can have transformed parents and the hit can be off-axis; both cases still use `matrixWorldInverse`. Targets behind the camera leave the last valid focal plane unchanged. Focus is clamped to near/far; orthographic Bokeh uses its corresponding depth define.

Rack focus uses `1-exp(-focusDamping*delta)`, giving frame-rate-independent exponential smoothing. A very large elapsed value does not force a focus jump; focus integration uses delta.

Click focus listens on **renderer.domElement**, not global window. Coordinates use its bounding rectangle, including page offsets. A primary left pointer down/up within 4 CSS pixels triggers selection; orbit drags do not. Points/lines/sprites and invisible hierarchy are ignored. Set `userData.excludeFromFocus=true` on a mesh/ancestor to exclude it, or supply `focusObjects`. Manual click releases tracking.

CPU raycasts see CPU geometry: GPU Bio-Motion bends are approximate and clustered instanced meshes disable raycasting entirely. Do not claim click selection of the actual GPU fish. Native skinned/morph raycasts follow Three.js's CPU support; transparency/alpha-cut texture picking is not texel-accurate in this helper.

### Deformation-aware depth

Stock BokehPass sets one global MeshDepthMaterial, which discards each fish's custom GPU position shader. This stack uses a pinned r180 subclass with per-group cloned depth materials, preserving `customDepthMaterial` compile/cache hooks. Bio-Motion and instanced cluster uniforms remain shared with the current pose/time, but borrowed shadow materials are never mutated or disposed by the stack.

Fallback MeshDepthMaterials handle ordinary/skinned/morph geometry, map/alphaMap/opacity and vertex-alpha cutouts, side, clipping and displacement. Materials with `depthWrite=false` do not write this depth. Non-mesh renderables are excluded through temporary layer masks, without hiding mesh descendants. Scene materials, background, override material, renderer clear/target state and shadow auto-update flags are restored with `finally`, including render errors. Cached depth clones are evicted when their surface source material is disposed; remaining clones are disposed with the stack.

This does not make arbitrary custom ShaderMaterial vertex deformation automatically work. Supply a compatible standard-chunk `customDepthMaterial` matching your custom surface, or use a different depth pass. Scene-wide custom override materials, alpha blending/transmission, glass and custom shader callbacks still need visual auditing. Transparent multi-layer depth/compositing is not solved. Bokeh's auxiliary depth is single-sampled, even when the scene color targets use MSAA.

## Size / DPR ownership

Provide a container with a stable explicit size. Defaults use renderer logical size when it has no container; no `window.innerWidth` assumptions or global pointer listeners are made. Initial `width`/`height`/`pixelRatio` can override these values. Drawing dimensions are CSS size × capped DPR exactly once; all composer passes resize through composer rather than ad hoc bloom resolution mutation.

`observeResize` defaults true when ResizeObserver exists and a container is available; hidden zero-size container observations are skipped. Call `resize()` manually in older environments or when renderer DPR policy changes. There is no automatic device-pixel-ratio media-query watcher.

By default `resize()` sets renderer DPR/size and perspective camera aspect. Orthographic frustum extents remain application-owned; only its projection matrix is refreshed. Set `resizeRenderer:false` when an existing framework owns renderer sizing; composer/camera still resize. Set `updateStyle:false` when your CSS explicitly sizes the canvas. Do not attach two competing resize owners. Texture-size limits and subpixel drawing buffers are rejected; memory allocation/driver budgets still require target-device profiling.

## Tuning defaults / starting ranges

Ranges below are **artistic starting points**, not calibrated physical constants or guarantees that only particular objects bloom.

| Config | Default | Suggested start / meaning |
|---|---:|---|
| exposure | 1.05 | HDR output exposure; scene/material-dependent |
| focusDistance | 4 | Positive axial distance in scene units; releases tracking when set via config |
| focusDamping | 4.5 | Exponential focus rate/sec; 0 freezes smoothing |
| aperture | .0012 | Try .0010–.0025; larger increases defocus |
| maxBlur | .006 | Try .005–.008; limits screen-space sampling radius |
| bloomStrength | .38 | Try .30–.45; reduces/increases glow, not exposure clipping prevention |
| bloomRadius | .65 | 0..1; bloom spread |
| bloomThreshold | .72 | Try .68–.78 for this art direction; threshold operates on HDR luminance |
| godRayIntensity | .16 | Try .12–.22; screen-space ray overlay |
| chromaticAberration | .0028 | Edge RGB offset in UV units; 0 disables |
| rippleStrength | .0005 | Micro-ripple UV amplitude; 0 disables |
| tintStrength | .14 | 0..1, luminance-based tint blend |
| waterTint | 0x06283d | Color, RGB hex number, or #hex string |
| sunScreenPosition | Vector2(.5,1.15) | Finite normalized screen position; can be outside image |
| vignetteOffset | .95 | Positive outer radius; shader uses correctly ordered smoothstep edges |
| vignetteDarkness | 1.25 | Radius multiplier |
| vignetteStrength | .55 | 0..1 edge darkening |
| snowIntensity | .012 | Procedural overlay brightness; 0 disables |
| bloomEnabled / bokehEnabled / underwaterEnabled | true | Independently bypass expensive passes |

Constructor-only options: `samples=4`, `maxPixelRatio=2`, `container`, `width`, `height`, `pixelRatio`, `observeResize=true`, `resizeRenderer=true`, `updateStyle=true`, `enableClickToFocus=true`, `focusObjects`, `autoFocusTarget=null`. Recreate when changing target/sample/dependency setup. Configuration values are finite/nonnegative with explicit ranges where applicable; invalid config is rejected before partial application.

```js
post.setConfig({bloomStrength:0.32, aperture:0.001, maxBlur:0.005});
post.setConfig({bokehEnabled:false}); // Save the extra depth/DoF workload.
post.setFocusTarget(rockModel);
post.setFocusDistance(6, true);       // Manual immediate snap, clears tracking.
post.resize(stage.clientWidth, stage.clientHeight, 1);
```

## Performance / verification

HDR ping-pong targets + MSAA + Bokeh depth + Bloom mip chains/full-screen filters cost memory and fill rate. A 500/1,000-fish instanced school can be cheap on CPU but expensive with these passes. No universal 60 FPS or cinematic appearance guarantee is made.

Run `npm run demo`, open `/instanced.html`, and enable **CINEMATIC POST FX**. Caustics/bubbles and shadows are independent toggles. Click rocks/floor for focus; initial tracking uses a CPU cluster. Default post-processing remains off to avoid hiding its incremental cost. Counters aggregate draw calls across all passes (`renderer.info.autoReset=false`, reset once per application frame), rather than reporting only OutputPass's fullscreen draw.

Profile complete frame time, memory, shader errors, depth/material alignment, silhouettes and target-GPU thermal behavior. Lower DPR, disable Bokeh/Bloom individually, reduce shadows and use optimized source geometry/textures when needed. CPU-only school benchmark numbers do not measure post-processing or GPU performance.

Automated tests cover real addon construction with a stub renderer, pass wiring/ownership, resize/DPR, focus/canvas interaction, depth shader-hook composition, exception cleanup and combined helper teardown. They **do not** establish live WebGL shader compilation, visual equivalence or measured device FPS. The production Vite build likewise verifies bundling, not GPU output.

## Ringkasan Indonesia

Stack ini menyediakan HDR/MSAA adaptif, Bokeh dengan depth yang mengikuti Bio-Motion/instancing, bloom berbasis luminansi dan lensa screen-space. Fokus memakai kedalaman ruang kamera, koordinat klik memakai canvas, serta resize mengikuti container. Semua pass/listener/target milik stack dibersihkan tanpa membuang renderer atau aset scene milik pemanggil.

Bloom tidak khusus ikan/caustics/gelembung; god-rays dan marine snow bukan volumetrik/partikel dunia fisik. Mode instanced hanya bisa dikunci ke pusat cluster CPU atau titik dunia, bukan memilih posisi individual ikan GPU secara akurat. Gunakan satu clock, satu updater animasi dan satu render composer per frame, dengan skala GLB terukur. Uji hasil visual dan performa di browser/GPU target; tidak ada jaminan 60 FPS.

## Optional interactive feeding

[Interactive Feeder](interactive-feeder.md) pools food/ripples and binds into the existing fixed-step cluster solver through `manager.setFeeder(feeder)`. Shift+click reserves the local gesture without stealing plain focus/bubble clicks or orbit drags. CPU cluster centers seek/consume and allow pitch/frenzy; there are no individual GPU mouth positions, per-fish CPU updates or per-fish matrix uploads. Packed matrix-row metadata carries tail rate without changing the 64-byte/cluster budget, and affine zeros are restored before transforms in all shader passes. The manager owns attached stepping; helper `feedingOptions` owns feeder disposal. Audio is optional/budgeted, never activated by feeding. See the contract for caps, kinematic limitations and validation boundaries.

## Optional dynamic day–night cycle

[Day–Night Cycle](day-night-cycle.md) interpolates optical keyframes and normalized HDR PBR emission in the existing frame owner. Register actual mesh/material parts after earlier shader injection; restore in reverse disposal order. No per-fish matrix writes, native animation replacement or emission in depth/normal/shadow shaders. `dayNightOptions` opts the cinematic helper into ownership; Director `dayNightCycle` exposes time/auto/duration/color and mirrors current optical values for JSON. The updating cycle takes precedence over independent optical presets, including when its hour is paused. It borrows lighting/post/caustic resources and leaves the last optical values on disposal. Screen rays and biological masks are stylized, bloom is not selective and PMREM is not regenerated. See the contract for bounds/axis validation and browser GPU verification limits.

## Optional cinematic camera ownership

[Camera Director](cinematic-camera-director.md) owns OrbitControls updates or automatic macro/CPU-cluster shots and synchronizes lens/focus through the real post API. `cameraOptions` opts the cinematic helper into construction, one update before day-night projection/render and reverse disposal; `cameraDirector` opts the GUI into mode/stand-off/auto/rotation controls and current aperture/JSON synchronization. C/N key bindings are explicit and ignore GUI typing. Zero visible clusters fall back safely. No per-individual GPU fish tracking, matrix readback/upload, true fisheye distortion or collision-safe rock/frustum navigation is claimed. Do not independently call controls.update or add another clock/render loop while bound.

## Optional water surface / impact binding

[Underwater Surface](underwater-surface.md) combines dielectric Fresnel/TIR with procedural sky/mirror colors, analytic height-field normals and eight bounded ripple slots. Helper `surfaceOptions` derives the audited tank plane and runs after day-night/before the existing post render; GUI `waterSurface` binds validated scalar setters. `surface.bindFeeder(feeder)` uses the new bounded `onFoodSpawn` subscription after successful nonzero drops, not a method monkey-patch. Mean-plane contact and camera medium classification are approximate; no actual reflected aquarium image, full Gerstner/CFD, dynamic Boids water-boundary collision or extra render/capture loop is claimed. Dispose subscriptions/owned mesh/material/geometry; borrow lights/scene/feeder and retain post depthWrite:false/focus exclusion.
