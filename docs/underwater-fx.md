# Underwater Caustics & Interactive Bubble Particles

## Files and compatibility

- Source: `mcp-server/codeDeployer/underwaterFx.ts`.
- Standalone template: `templates/underwater-fx.js`, regenerated by `npm run build`; imports only `three`.
- Package export `threejs-instant-deployer-skill/underwater-fx`: `createUnderwaterFX(THREE)` returns `{injectWaterCaustics,InteractiveBubbleSystem}` without importing Three.js in server-only code.
- Full lifecycle helper: `examples/underwater-aquarium.js` composes the existing aquarium helper with FX.
- Browser review surface: `/boids.html` in `npm run demo` now includes an underwater-FX toggle. Fish are synthetic, not downloaded GLBs.

The shader contract targets **Three.js r180 WebGLRenderer**, not WebGPURenderer/TSL. Default tests validate source composition, buffers, transforms, lifecycle and CPU math; they do not compile shaders on a live GPU or establish visual correctness. Use matching Three.js/addons and review the target browser/device.

## Water caustics API

```js
import {injectWaterCaustics} from './templates/underwater-fx.js';
const caustics = injectWaterCaustics(floor.material, {
  color: 0x88ccff,
  intensity: 1.4,
  scale: 0.75,
  speed: 1.2,
  waterLevel: 4,
  depthFalloff: 0.15
});
caustics.update(elapsedSeconds);
// Backward-compatible uniform API: caustics.value = elapsedSeconds;
caustics.setIntensity(0); // Uniform branch skips Voronoi work while disabled.
// Teardown before disposing floor material: caustics.dispose();
```

The returned object is itself the `uCausticTime` uniform (`.value`) and a lifecycle controller. `.uniforms` exposes all shared uniform objects. `update`/`setIntensity` validate finite nonnegative inputs; direct `.value` writes are the caller's responsibility. Color must produce finite components. `intensity`, `speed`, `depthFalloff` are nonnegative; scale is positive; `waterLevel` is any finite world Y. Presets are artistic defaults, not calibrated underwater optics.

Built-in Standard/Physical, Basic, Lambert and Phong materials are accepted; ShaderMaterial/RawShaderMaterial/depth/NodeMaterial are not. The material is patched **in place**, so all meshes sharing it receive the same effect/uniforms. Clone and preserve existing callbacks explicitly if per-instance effects are needed; Three.js Material.clone does not copy compile/cache hooks automatically. Use one controller per actual material instance, not per mesh traversal occurrence; duplicate direct injection is an explicit error.

### Shader placement and composition

The vertex varying captures `modelMatrix * transformed` after `project_vertex`, with batching/instance transforms included. It does **not** use undeformed `position` at `begin_vertex`, which would cause caustics to slide incorrectly on Bio-Motion surfaces. Because the hook composes with prior hooks and leaves Three.js chunks in place, Bio-Motion may be applied before or after it without the world-position varying preceding deformation.

The fragment code uses animated two-frequency Voronoi cell-edge distances to create a bright network. It adds color to linear `outgoingLight` **before** `opaque_fragment`, tone mapping, output colorspace conversion, fog, and dithering. Above `waterLevel` the effect is off; below it, `depthFalloff` exponentially attenuates the overlay. Intensity zero avoids the Voronoi loop via a uniform-controlled branch. Caustics do not replace surface materials or their PBR properties.

Previous compile hooks run with their original `this` and renderer arguments. Cache keys retain the earlier hook/default key or dynamic custom key and add a caustics version tag. Uniform/controller metadata is clone-safe (no circular enumerable references). Repeated shader composition has an idempotency marker to prevent duplicate GLSL declarations, including inherited callbacks on cloned materials.

Disposal is idempotent, disables intensity, restores owned hook/cache/userData state if still installed, and marks the material for recompilation. It **never** disposes caller-owned material/textures. If a later unrelated shader wrapper is installed, disposal does not clobber that wrapper: the older caustic code can remain composed with zero intensity. Prefer reverse installation order for full restoration: attach caustics after Bio-Motion cloning, dispose caustics before the Bio-Motion controller and GLTF resources.

This is a **stylized world-XZ light overlay**, not an optical water simulation. It is not shadow/occlusion aware, does not infer a water volume, trace refracted rays, conserve light energy, or account for arbitrary surface-facing projection. Large fullscreen coverage costs two 3×3 Voronoi searches per affected fragment. Profile real hardware, reduce affected surfaces/intensity, or disable the module; no universal GPU budget is promised. Existing arbitrary custom shader changes may still require manual integration.

## Bubble API

```js
import {InteractiveBubbleSystem} from './templates/underwater-fx.js';
const bubbles = new InteractiveBubbleSystem(scene, 400, worldBounds, {
  seed: 42,
  interactionRadius: 0.8,
  pushStrength: 0.8,
  size: 0.08,
  opacity: 0.65
});
bubbles.update(deltaSeconds, elapsedSeconds, aquarium.fishInstances);
// Or pass world-space THREE.Vector3 positions, not local mesh.position.
// Teardown: bubbles.dispose();
```

Constructor signature remains `(scene, count=300, boundsBox?, options={})`. Bounds default to world Box3 `[-4,0,-3]..[4,4,3]` and are cloned. They must have finite positive dimensions. Scene/Group parent transforms must be finite/invertible. Particle count is integer 0–100,000; this is an input safety cap, **not** a performance promise at that count.

| Option | Default | Meaning |
|---|---:|---|
| seed | 89173 | Safe integer for deterministic respawn/phase RNG |
| random | seeded RNG | Optional function returning finite `[0,1)` |
| interactionRadius | .8 | World sphere range for fish repulsion |
| pushStrength | .8 | Maximum combined horizontal particle push speed, world units/s |
| minRiseSpeed / maxRiseSpeed | .6 / 1.8 | Per-particle sampled vertical world speed |
| fixedDelta | 1/60 | CPU fixed timestep |
| maxSubSteps | 12 | Maximum work per update |
| maxFrameDelta | .2 | Pause/backlog clamp; discarded time is recorded |
| color | `0x99ddff` | Bubble sprite tint |
| size | .08 | Approximate world diameter of point sprite |
| opacity | .65 | Nonnegative additive alpha multiplier |
| maxPointSize | 64 | Sprite pixel-size cap; hardware may impose a lower cap |

The CPU state lives in reusable Float32 position/speed/amplitude/phase arrays. Position BufferAttribute uses DynamicDrawUsage and uploads only after steps or explicit particle reset. Seeded fixed-step integration gives the same trajectories at 30/60 FPS for identical static fish inputs and work limits. Moving fish snapshots at different sampling rates can differ; that is not a fluid solver.

Wobble uses differences of an analytic sinusoidal displacement across each fixed step, not an unconditional per-frame offset. Rise, push and respawn are timestep-based. Particles reaching the surface reset to minimum Y with new sampled properties; X/Z stay within bounds. `resetParticle(index, randomY=false)` is available for explicit respawn, validates indices, and marks the position buffer for upload. Initial particles distribute through the water column.

Fish inputs are either world Vector3 objects or Boids records with a world `.position`. Pass `aquarium.fishInstances` **after** `aquarium.update(delta)` to avoid a per-frame map/allocation and to use its current world snapshot. Never pass `fish.mesh.position` when a parent is transformed; that is parent-local. Invalid/nonfinite inputs fail explicitly.

A fish spatial hash limits particle interactions to 27 neighboring cells. No Vector3 is created for each particle or particle/fish pair. Push is horizontal, capped even with many nearby fish, and coincident positions receive a deterministic phase-based direction rather than NaN. Dense cells can still approach particle×fish work; this is not a guarantee for arbitrary schools.

Geometry coordinates remain **world-space** even under translated/rotated/nonuniformly scaled parents: the Points object cancels its parent's world transform. It is a system-owned draw object; do not manually animate its transform. Culling is disabled because parent updates can otherwise produce stale bounds before the render callback. `onBeforeRender` synchronizes the transform and drawing-buffer height; perspective/orthographic point sizing is supported.

A custom ShaderMaterial uses circular `gl_PointCoord` rim/highlight alpha, not square point sprites. It is transparent/additive, depth-tested, and depthWrite=false, with explicit tone-mapping/colorspace chunks. It does not implement physically refractive spheres, soft depth intersections, fog scattering or per-particle transparency sorting. Driver point-size limits still apply.

`update(delta,elapsed,fishPositions=[])` validates finite nonnegative seconds and monotonic elapsed time. Delta zero leaves positions/upload version unchanged. Large pauses/backlogs are discarded to bound work; `stats.droppedTime` records cumulative discarded seconds. Internal fixed-step wobble time can lag external elapsed after discarded time, avoiding an explosive catch-up. `stats.subSteps`/`neighborChecks` describe the last update, and `respawns` is cumulative. `dispose()` removes only its Points and disposes its owned geometry/material; scene/fish/floor resources remain caller-owned. Further updates after disposal fail explicitly.

No particle–rock collision, buoyancy physics, pressure, fish steering feedback or actual air/water refraction is simulated. This is a one-way decorative response to fish positions. Audit particle count, fill rate, bounds and visibility on the target device.

## Full scene integration

The following augments an **existing** client scene/camera/renderer and measured `fishManifest`. Supply audited world bounds and adequate lighting/environment. Merge update calls into the existing loop rather than starting a second one.

```js
import * as THREE from 'three';
import {deploySmart3DModel, updateAllDeployedModels} from './templates/smart-deploy.js';
import {BoidsAquariumManager} from './templates/boids-manager.js';
import {injectWaterCaustics, InteractiveBubbleSystem} from './templates/underwater-fx.js';

const floorMaterial = new THREE.MeshStandardMaterial({color: 0x3d2817, roughness: 0.8});
const floor = new THREE.Mesh(new THREE.PlaneGeometry(10, 10), floorMaterial);
floor.rotation.x = -Math.PI / 2;
floor.receiveShadow = true;
scene.add(floor);
const waterBounds = new THREE.Box3(new THREE.Vector3(-4, 0, -3), new THREE.Vector3(4, 4, 3));
const caustics = [];
const patchedMaterials = new Set();
function attachCaustics(material, intensity) {
  if (patchedMaterials.has(material)) return;
  caustics.push(injectWaterCaustics(material, {intensity, waterLevel: waterBounds.max.y}));
  patchedMaterials.add(material);
}
attachCaustics(floorMaterial, 1.6);
const bubbles = new InteractiveBubbleSystem(scene, 400, waterBounds, {seed: 42});
const aquarium = new BoidsAquariumManager(scene, {bounds: waterBounds, seed: 42});
const handles = [];
let disposed = false;

for (let i = 0; i < 8; i++) {
  handles.push(deploySmart3DModel('/models/BarramundiFish.glb', {
    scene,
    manifest: fishManifest, // Measured recommendedScale, never a guessed constant.
    bioPreset: 'fish_swim',
    onLoaded: ({model, bioController}) => {
      aquarium.addFish(model, bioController, {randomizePosition: true, deformationMargin: 0.08});
      model.traverse(child => {
        if (child.isMesh) for (const material of Array.isArray(child.material) ? child.material : [child.material]) {
          attachCaustics(material, 0.65); // After Bio-Motion cloned surface materials.
        }
      });
    }
  }));
}
const clock = new THREE.Clock();
let elapsed = 0;
renderer.setAnimationLoop(() => {
  const delta = clock.getDelta(); // Exactly one clock read.
  elapsed += delta;
  aquarium.update(delta);
  for (const controller of caustics) controller.update(elapsed);
  bubbles.update(delta, elapsed, aquarium.fishInstances);
  updateAllDeployedModels(delta, elapsed);
  renderer.render(scene, camera);
});
try {
  await Promise.all(handles.map(handle => handle.ready));
} catch (error) {
  disposeUnderwater();
  throw error;
}

// Also call from the application's normal unmount/teardown lifecycle.
function disposeUnderwater() {
  if (disposed) return;
  disposed = true;
  renderer.setAnimationLoop(null);
  for (const controller of [...caustics].reverse()) controller.dispose();
  bubbles.dispose();
  aquarium.dispose();
  for (const handle of handles) handle.dispose();
  floor.removeFromParent();
  floor.geometry.dispose();
  floorMaterial.dispose();
}
```

For asynchronous setup and disposal without hand-wiring callbacks, use `createUnderwaterAquarium` from `examples/underwater-aquarium.js`. Pass an existing `floorMaterial`, world `bounds`, URLs and measured manifests for fish/rock. It registers the rock before random fish spawning, attaches surface caustics after Bio-Motion, and cleans up pending/error loads. Its `update(delta,elapsed)` already calls the single global shader/mixer updater; **do not also call updateAllDeployedModels in that same loop**. Caller still owns floor/renderer/environment resources.

## Ringkasan Bahasa Indonesia

- Caustics adalah overlay prosedural XZ dunia sebelum tone mapping, bukan simulasi refraksi fisik. Posisi mengikuti vertex yang sudah dideformasi Bio-Motion.
- Gelembung memakai sprite bundar, buffer reusable, fixed timestep dan hash neighbor ikan. Tidak ada tumbukan dengan batu atau simulasi fluida.
- Berikan record `aquarium.fishInstances` dalam world-space, bukan posisi lokal mesh. Clock dibaca sekali dan updater shader/mixer dipanggil sekali.
- Patch material hasil clone Bio-Motion, lalu dispose dengan urutan terbalik. Uniform `.value` tetap kompatibel; controller `.update`/`.dispose` lebih eksplisit.
- Bounds, permukaan air, jumlah partikel dan budget GPU harus diaudit pada project pengguna. Tes offline tidak memverifikasi tampilan/kompilasi pada GPU browser target.


## Clustered instanced schools

Caustics can be attached to each instanced manager's owned surface material after construction; the composed varying observes final GPU school/Bio-Motion positions. Dispose those controllers before the instanced manager. Its `getInteractionSources()` returns only **cluster center records** for coarse bubble influence, not exact GPU fish positions. Do not present this as individual fish/bubble interaction; an exact per-fish CPU readback would change the intended performance architecture. See [Instanced Boids](instanced-boids.md).

## Interactive Director setters

Caustic controllers expose `setSpeed(value)` (finite nonnegative), `setColor(Color|RGBHex|#hex)` and a `disposed` getter, alongside existing setIntensity/update/dispose; shared `uniforms` are available before compilation. Bubble systems expose `setRiseSpeed(multiplier)` for existing sampled rise velocities and `setOpacity(nonnegativeMultiplier)` for `uBubbleOpacity`—not the unused ShaderMaterial.opacity field. Rise multipliers leave sampled arrays unchanged and zero pauses vertical rise while wobble/interactions may continue. Opacity is additive alpha multiplier and can exceed one for expert use; normal Director range starts 0..1 (expanded to retain larger initial values). [Director Studio](aquarium-director.md) routes controls correctly and owns no extra updater/render loop.
